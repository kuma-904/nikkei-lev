# 赤青ナビ — 日経レバレッジ投信 判断ダッシュボード

日経平均の **楽天日経平均ブル4.3倍 / ベア3.8倍** を売買するための、個人用の判断ダッシュボードです。
GitHub Pages に置けば、スマホからURLでアクセスできます。

- **テクニカル自動取得**：日経平均の日足を GitHub Actions が定期取得
- **オーバーナイト要因**：前日の米国株(S&P500)・ドル円・日経先物を取り込み、判定に反映＋専用予測を表示
- **データの取得状況**：各データの時点・取得元・最終取得・次回取得予定をサイト上に表示
- **過去の的中率（バックテスト）**：ルールベース判定と過去データ予測の的中率を表示（予測は先読みなしのウォークフォワード）。重み・しきい値・遡り年数の調整に連動して再計算し、『自動で探す』で的中率が最大になる設定を自動セット（テクニカル中心・売買コスト除く・過剰最適化に注意）
- **手動更新ボタン / バージョン表示**：公開済みの最新データをその場で再読み込み。フッターにアプリのバージョンを表示
- **お知らせ・更新履歴ページ**：トップの「🔔 お知らせ」から各バージョンのリリース内容を閲覧（#news 表示・ブラウザの戻る対応）
- **実運用の実績（フォワード）**：毎日の予測を data/predictions.json に記録し、翌日の結果で採点した“本番の成績”を表示（バックテストの過去当てはめとは別の、後出しなしの記録）
- **資金・ポジションサイズ**：総資金と1トレード許容リスクから、推奨ポジションと1日の想定損益を計算（端末内のみ保存）
- **タイプ診断・プリセット**：順張り／逆張り／海外重視などで重みとしきい値を一括切替、3問のかんたん診断つき
- **3つの見立ての一致サマリー**：ルールベース・予測・海外の向きが揃っているかを判定パネル下に表示
- **ルールベース判定**：7指標を集計して「ブル寄り / ベア寄り / 様子見」を表示
- **過去データ予測**：今と同じ相場状態だった過去の日の「翌日の値動き」から上昇確率を推定
- **初心者対応**：指標カードや用語をタップすると解説が下から出ます

## 仕組み（データの流れ）

```
GitHub Actions (毎営業日)               GitHub Pages (静的配信)
┌──────────────────────────┐         ┌────────────────────────┐
│ scripts/update_data.py    │         │ index.html             │
│  1. 日経平均を取得(stooq)   │  push   │  └ assets/app.js が    │
│  2. テクニカル計算          ├────────▶│     data/data.json を  │
│  3. 判定・予測             │ commit  │     読んで描画          │
│  4. data/data.json 出力    │         │                        │
└──────────────────────────┘         └────────────────────────┘
```

GitHub Pages は静的サイトなので計算はできません。**取得と計算は Actions 側で回し、結果の `data.json` をサイトが読むだけ**にしてあります。これが一番シンプルで壊れにくい構成です。

## セットアップ手順

### 1. リポジトリを作る
GitHub で新しいリポジトリ（例：`nikkei-lev`）を作り、この一式をすべてアップロード（またはコミット＆プッシュ）します。**Public** にすると GitHub Pages が無料で使えます。

### 2. GitHub Pages を有効化
リポジトリの **Settings → Pages** で
- Source: **Deploy from a branch**
- Branch: **main** / **/(root)** を選んで Save

数分後、`https://<ユーザー名>.github.io/nikkei-lev/` で公開されます。

### 3. Actions に書き込み権限を付与（重要）
定期更新でボットが `data.json` をコミットできるように、
**Settings → Actions → General → Workflow permissions** で
**Read and write permissions** を選んで Save。

### 4. 初回のデータ更新を手動実行
**Actions** タブ →「update-data」→ **Run workflow** を1回押すと、実データを取得して `data/data.json` が更新されます。
以降は **平日 8:00〜20:00 の毎時（JST）** に自動で回ります。日足データのため日中は基本変わりませんが、引け後の当日データを早めに拾い、「時点/次回更新」を新鮮に保つ狙いです（頻度を上げても Public リポジトリなら無料。変化がなければコミットしません）。

> 💴 **料金**：Public リポジトリの標準ランナーは**無制限で無料**（全プラン共通）。この頻度なら費用ゼロです。Private にすると月2,000分の無料枠→超過課金なので、Public 推奨。
> ⏰ cron は数分〜十数分ずれます。手動実行（Run workflow）はいつでも可能。
> 😴 スケジュールは**リポジトリが60日無活動だと自動停止**することがあります。ボットのコミットで基本は生き続けますが、たまに手動実行しておくと確実です。

### 5. スマホに登録
公開URLをスマホで開き、ブラウザの「ホーム画面に追加」を実行するとアプリのように使えます（`赤青ナビ` アイコンが出ます）。

## 1日運用での使い方

この2本は**投資信託**で、株やETFのように場中で瞬時に往復できません。1日1回計算される**基準価額**で約定します。「1日で解約」は実務上〈申込 → 翌営業日以降に解約〉となり、損益はおおむね **倍率 ×（保有日の日経の1日リターン）** で決まります。

- **主役の数字**は「過去データからの予測（＝翌日の方向）」。ここが当たるかどうかで勝敗が決まります。
- **減価はほぼ無視でOK**（複数日の再計算で効くもの。1日保有なら発生しません）。
- 効くのは**往復コスト**（信託報酬の日割り・信託財産留保額・購入時手数料など）。値動きでこれを上回る必要があります。
- **申込締切は15:20**。このファンドの購入申込締切は **15:20**（東証の引け15:30より10分早い）。締切前ならその日の基準価額、締切後は翌営業日の基準価額になります。15:20時点では当日終値が未確定なので、注文は「引け直前の水準を見ながら翌日の方向に賭ける」形になります。約定日・受渡日も含め最新条件は**楽天証券で必ず確認**を（損益が乗る「保有日」がこれで決まります）。

> 運用フロー例：夜の更新で翌営業日の方向を確認 → 締切前に注文 → 翌営業日以降に解約。

> 🌅 **オーバーナイト要因は朝が本番**：前日の米国株・ドル円は前夜に確定します。夜間更新の時点では「次のセッションを動かす今夜の米国」はまだ起きていないため、オーバーナイト要因は朝（8:00更新後）に確認して当日のセッションに賭けるのが効果的です。テクニカルの土台＋オーバーナイトの二段構えで見てください。

## 中身の見方

| 表示 | 意味 |
|------|------|
| **今日の判断** | 7指標の重み付き合計を −100〜+100 のスコアにし、+20以上でブル寄り／−20以下でベア寄り |
| **綱引きメーター** | スコアの位置。右(赤)に寄るほどブル、左(青)に寄るほどベア |
| **確信度** | スコアの絶対値（5段階）。強いほど点灯が増える |
| **過去データからの予測** | 「トレンド × RSI × MACD」で今の局面を分類し、過去の同局面の翌日上昇率を集計 |
| **テクニカル指標** | カードをタップで解説。●が赤=強気／青=弱気／金=中立 |
| **レバレッジ投信の特性** | 本日の日経変動 × 倍率の目安と、減価リスク（直近ボラから判定） |

## サイト上で数字を調整（プレビュー）

サイトの下部に「数字を調整」パネルがあり、以下をスライダーでその場で変えられます。判定・予測が即座に計算し直され、設定は**その端末の localStorage にだけ**保存されます（日々のデータは次回更新まで固定）。

- **遡り年数**（1〜8年、既定5年）… 予測が参照する過去の期間
- **最小サンプル数**（既定8）… 類似局面がこれ未満なら条件を広げる
- **判定しきい値**（既定±20）… ブル寄り/ベア寄りに振れる強さ
- **各指標の重み**（7項目）… ルールベース判定への効き

「判定と予測の仕組み」セクションに、計算式と現在のパラメータも表示しています。

## 既定値を変える（サーバ側）

サイトの初期値そのものを変えたいときは `scripts/update_data.py` の上部定数を編集します。

- **倍率**：`BULL_MULT = 4.3` / `BEAR_MULT = 3.8`
- **遡り年数の既定**：`LOOKBACK_YEARS = 5`（サイトのスライダーは最大 `SHIP_YEARS = 8` 年ぶんのデータを出荷）
- **最小サンプル数**：`MIN_SAMPLES = 8`
- **判定しきい値**：`SCORE_THRESHOLD = 20`
- **申込締切の表示**：`ORDER_CUTOFF = "15:20"`
- **各指標の重み**：`indicator_signals()` 内の `weight=...`
- **予測の分類**：`classify()` の `regime` / `rsi_zone` の区切り
- **更新頻度**：`.github/workflows/update-data.yml` の `cron`

`index.html` は `data/data.json` のスキーマに沿って描画しているだけなので、
指標を足したいときは Python 側で `indicators` に1件追加すれば、フロントに自動でカードが増えます（解説を出すなら `assets/glossary.js` に同じ `id` で項目を足す）。

## ローカルで確認する

`file://` で開くと `fetch` がブロックされるので、簡易サーバ経由で開いてください。

```bash
pip install -r scripts/requirements.txt
python scripts/update_data.py --sample   # 合成データで data.json を生成
python -m http.server 8000               # http://localhost:8000 を開く
```

`--sample` を外すと実データ取得を試みます（取得できなければ自動で合成データにフォールバックし、`サンプルデータ` バッジが出ます）。

## データ元

- 日経平均 … 主：**stooq**（`^nkx` 日足CSV、APIキー不要）／副：**Yahoo Finance**（`^N225`）
- 米国株 … **stooq `^spx`** ／副 `^GSPC`（S&P500）
- ドル円 … **stooq `usdjpy`** ／副 `JPY=X`
- 日経先物 … **Yahoo `NIY=F`**（CME・EOD・任意。取得できない場合は自動で非表示）

海外系はどれか取れなくても、その指標だけ自動で無効化され、残りで動きます。

判定・予測は日経平均**指数**のテクニカルに基づきます（ブル/ベア投信はこの指数に倍率で連動するため、まず指数の向きを読むのが出発点です）。
